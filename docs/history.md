# 历史变更

当前行为以 [README](../README.md) 和 [机器使用说明](machines.md) 为准。本页保留版本变化及旧实现记录。

## 近期版本

### 0.2.19

- 多线程联合代理改用内部默认 1024 槽样板栏，按真实槽位顺序启动；不再强制样板总成，保留其输入与共享催化剂支持。
- 中键编辑样板的产量估算、耗能分配、并行与 OC；支持算式、电压单位、超限提示和首产物图标。参数跟随样板，库存随主机保存。
- 主机可连接 AE，统一查询 PH 工具状态；样板输入物、输出物、配方池支持独立拼音搜索。两种代理的主机栏搜索改为只显示匹配结果。


### 样板编码修复

- 手动点击终端编码按钮时，跳过完整输入数组中的空槽，修复服务端 `GtnrToolPatterns.encode` 空指针导致的断连。
- 恒星冶炼配方省略特殊槽中的白矮星锭模具，不将其记为普通输入或 NC 工具；重新编码此前受影响的样板即可应用。

## 旧版实现摘录

以下段落从旧 README 提取，包含当时的版本、迁移说明及已移除功能，不作为当前兼容性说明。

新增独立机器“多线程联合代理”（默认 MTE ID `31994`，注册名 `gtnhadjust.threaded_joint_proxy`），在工作台用一个 GTNL 合金搅拌炉控制器无序合成。0.2.13 起使用 GTNH 2.9.0 原版量子操纵者（`MTEQuantumForceTransformer`）的完整 15×21×15 结构，主机替换成本机器，主机偏移沿用原版 `(7, 20, 4)`。脉冲操纵者和屏蔽核心全部固定为最低级：分别为 `blockCasings5Misc:7` 和 `blockCasings5Misc:11`，不接受其他等级；量子力导体、框架和力场玻璃沿用原版材料。结构预览、建造提示及生存建造使用同一套固定材料定义。

0.2.12 起取消配方池白名单，改用与代理联合工厂相同的真实多方块定位器库存。多个定位器共同提供其记录控制器公开的全部已注册配方池，每张样板仍按 `gtnrPatternRecipeMap` 选择配方池；缺少池信息、没有定位器提供该池或配方输入产物不匹配时不启动。主机槽不再用于开放配方池，旧槽内控制器保留，可自行取回；已有线程及其进度、产物 NBT 保持原格式，新线程需先配置定位器。

GUI 为每张已装样板显示一个条目，顺序为总成维度和坐标、总成内样板槽位。0.2.12 起运行条目与代理工厂一样使用产物图标和两行信息：第一行青色产物名称，第二行为 `产量x 当前运行时间/总耗时 耗能eu/t 同时并行数x 实际超频次数`，时间单位为秒。只取样板原始产出顺序中的第一个产物，不使用配方中未写入样板的其他产物替代；流体数量以 L 显示。产量按该种产物的配方标称数量乘以本轮总加工次数计算，包含批处理；同种产物涉及概率输出时加 `~`，例如必出 12 铝粉和概率额外 4 铝粉显示为 `~16x铝粉` 再乘以本轮加工次数，实际输出仍按原配方概率生成。并行列表示同时加工的数量，不把额外批次计入该列。

0.1.65 起在原线程 NBT 中追加显示元数据，保留原有进度和产物格式。旧线程继续运行，按现有样板尝试从保存的耗电、加工次数和耗时还原并行/超频；不能唯一还原的参数显示 `?`，下一次启动后完整记录。0.1.66 起缺电跳停清空所有线程，更新结构按钮强制刷新控制器和样板缓存，线程行统一左对齐。旧版本已经以 GT 缺电跳停状态保存的残留线程，也在读档时清除；单纯手动暂停的存档不清除线程。0.1.67 起允许共享输入并均分原料，安装蓄水仓后免除配方用水，并加入稀土综合处理的粉末/矿石白名单池。客户端和服务端需同时更新并重启。这些显示、调度和修复随原有 `threadedJointProxy` 开关启停，无新增 Mixin 或独立开关。

0.2.6 起，代理联合工厂的 GUI 状态页在供电说明下方显示 AE 网络连接状态，方块悬停的 Waila 提示框也显示同一行。已连接使用绿色“AE网络：已连接”，未连接使用红色“AE网络：未连接”；两处均读取服务端主机的 AE 节点可用状态，与产物交付所需的状态一致，节点未就绪、断网、网络缺电、缺少可用频道或网络启动中均显示未连接。输入和运行模式均显示，不改变频道消耗、供电、加工或产物等待交付机制。此提示随 `proxyFactory` 功能使用，无新增开关；适配 GTNH 2.9.0、GTNR 0.1.47、AE2 rv3-beta-1095 和 Waila 1.19.34，更新后客户端与服务端同步重启。游戏内需验证接线/断线、AE 断电、频道不足时两处文字和颜色随状态更新。

代理工厂的配方池不再经过白名单筛选，也取消默认开放的 25 个池；由定位记录的控制器公开的 `getAvailableRecipeMaps()` 建立“配方池→第一个记录”的索引，只索引已注册配方池。索引在定位器槽位变化或读档时重建，不访问目标世界。相同配方池始终使用最先提供它的记录；该目标失败时不尝试后面的同池目标。旧白名单文件和查询保留，0.2.12 起两种代理均使用定位器提供的全部已注册配方池。第三方机器需要通过 GT 多方块及配方池接口公开加工能力，自定义非配方池加工流程仍需专门接入。

工业高炉配方池额外要求有效热量达到配方 `mSpecialValue`：源机器的线圈基础热量，加上代理工厂自身电压按原版高炉计算的每级 100 K 加成（MV 为基准）。无线模式使用 MAX 电压计算该加成；不使用源机器电压或其已经叠加折扣/加成的总热量。线圈按目标类中实际的 `HeatingCoilLevel` 状态字段读取，字段定位按类缓存；无法读取时明确拒绝启动。热量不足沿用 GT 原生提示。0.2.11 起，诸神锻炉高炉模块（`MTESmeltingModule`）使用模块当前 `getHeat()` 返回的有效加工炉温直接比较配方需求，不要求线圈，也不叠加代理工厂的电压温度；`getHeatForOC()` 是另一项超频温度，不用于配方温度准入。有效炉温由诸神锻炉按自身燃料倍率和升级计算并更新，本模组不改写或重算模块状态。普通线圈机器仍沿用前述线圈基础热量加代理电压温度的规则；不支持的无线圈机器仍拒绝，后续需按原机器算法分别接入。此修复随 `proxyFactory` 启停，无新增独立开关；兼容 GTNH 2.9.0 / GregTech 5.09.54.265，更新后两端重启。开启默认关闭的 `general.debug` 可用 `[proxy-heat]` 查看诸神模块有效温度和配方要求，游戏内验证温度不足、恰好达标、燃料倍率/升级变化及普通线圈高炉回归。仅增加温度准入，不继承源高炉的热量折扣或热量超频。`ProxyRecipeRequirements.register` 提供按配方池注册或替换额外启动条件的扩展入口；其他配方池暂按代理工厂现有加工规则运行。

0.2.10 起，手持已记录主机的定位器，对空气普通右键可显示目标主机的青色穿墙轮廓，持续 15 秒，并在聊天中显示维度和坐标。潜行对空气右键会先寻找目标附近的安全站立位置，成功传送后朝向目标并高亮。对着方块右键不触发导航；潜行点击多方块主机继续沿用原来的记录/重新记录行为，其他方块按原有交互处理。空白定位器不触发导航。

`config/gtnhadjust-features.properties` 的 `lootSimulator` 默认开启；`config/gtnhadjust.cfg` 的 `lootSimulator.mteId` 默认 31992，取得或放置控制器后不要更改。修改开关或 ID 后重启，客户端和服务端应保持一致；关闭前应先移除现有控制器。`general.debug` 可记录周期目标数和缺少 MobsInfo 数据的实体。工业屠宰场的装备销毁和固定时运 Mixin 已移除，旧配置中的 `crusherEquipmentVoid`、`crusherFixedLooting` 不再生效，原机器恢复自身逻辑。

0.2.4 起，“超级碎片世界采集器”更名为“物质解压器”（Matter Decompressor），结构完整采用 GTNH 2.9.0 原版亚稳态黑洞遏制场的布局，尺寸为 35×35×33（宽×深×高）。主机位于原版主机位置，即底部第六层；超高密度弯曲机械方块、背景辐射吸收机械方块及 144 个硅岩合金框架保留原位置。原版 64 个霍金辐射重组焦点位置全部改成同一等级的等级玻璃；升级的就是这些位置的玻璃，继续提供原有线程、耗能及耗时加成。其余位置不增设玻璃。使用全息投影仪按新结构建造。

0.2.5 起，黑洞中心使用本模组独立实现的纯黑球形阴影和细窄冷白光子环视觉，不再调用 GT 原生黑洞模型，也没有吸积盘。轮廓亮边按实际视点的球面切圆定位，近看、斜看和第三人称视角下均跟随黑洞轮廓。外侧包围一层完整的淡蓝灰色半透明球形约束场：球面边缘微亮，表面稀疏细纹和局部物质化斑纹缓慢旋转、流动，黑洞轮廓亮度也缓慢转动。金色物质脉冲已移除；四向解压喷流改用更清晰的冷白核心、淡蓝辉光、连续向外传播的亮度变化和加宽双螺旋流线，扩散光环以细亮边和柔和辉光从约束场向外扩散、淡出。颜色以冷白、浅蓝和蓝灰为主，体现受控能量流与约束场的视觉分工。

0.2.8 起，鼠标放在 NEI 书签组左侧竖线上，按 V 对该组的 GT 多方块主机排序：先比较水平短边，再比较水平长边、高度，最后按客户端显示名称排序，均为升序。例如 4×2×3 排在 3×5×2 之前。尺寸来自实际 StructureLib 定义的尺寸元数据和最小档构造流程，不读取 tooltip；使用独立主机副本和数量为 1 的构造触发物，拦截 GT `buildPiece`，合并本次实际选择的所有结构片段及偏移，不放置方块或生成投影。读取失败、非标准定义、构造流程依赖世界状态或无法取得构造片段的主机一起移到单独的新书签组；非主机书签保留在原组。对于数量/通道以外控制的自定义可变结构，只有该主机默认构造路径能表达的最小尺寸可读取，不能确认时归入未知组。

GT-Never-Reset 0.1.32 已在 NEI 导入时将切割机展示配方池映射到真实配方池，本模组不再注入旧的 `factoryRecipeMapFix`。此前已编码且记录了展示配方池的旧样板不会自动迁移，遇到通用联合工厂无法匹配时需重新从 NEI 导入并编码；其他配方池不受该撤除影响。


小型量子操纵者及其专属配方已移除。旧的 `smallQuantumMachine` 和 `quantum` 配置不再生效；客户端与服务端需同时更新并重启。
