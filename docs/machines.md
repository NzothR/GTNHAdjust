# 机器使用说明

所有机器面向 GTNH 2.9.0。配方、材料及结构可在游戏内通过 NEI 和全息投影仪查看；客户端与服务端使用相同模组版本及玩法开关，更新后重启。

## 初代目行星发动机投影

手持多方块机器投影仪，执行 `/sl_channel set structure_render 1`，再右键主机。默认的 `structure_preview=1` 在当前区块内预览最多 4 层的全部结构方块，省略粒子和逐块错误检查。用 `/sl_channel set structure_section <编号>` 选其他分区，用 `/sl_channel unset structure_section` 回到主机分区。编号按 X 区块、Z 区块、Y 高度带递增。

用 `/sl_channel set structure_preview 2` 改看整机外框。它只绘制长方体的边线，聊天显示世界 X、Z 和 Y 的完整尺寸，方便量占地。切换任一模式时替换上一次发动机预览。

潜行右键按 GTNL 原生流程建造，预览模式和分区编号只控制客户端显示。生存建造使用 StructureLib 的投影仪预算和取料方式，每次成功放置后延迟 50 tick 做完整结构检查。连续建造时重新计时。适配 GTNL dev-290 和 StructureLib 1.4.47，`planetaryEngineProjector` 默认开启，两端同步并重启。

## 两种代理共用的定位机制

潜行右键 GT 多方块主机，将其维度、位置和主机身份记录到定位器。打开代理 GUI，进入输入模式放入定位器，再切换运行模式。默认 128 格，容量由 `proxyFactory.locatorSlots` 控制；支持主机名和配方池名搜索，安装 NECH 时支持拼音。

定位器提供记录控制器公开的全部已注册 GT 配方池。不同定位器可以提供不同池；同池使用槽位顺序中的第一个来源，不自动回退其他来源。第三方自定义加工流程需要单独适配。新线程启动前，来源维度和区块必须已加载、主机身份一致、结构已成型；代理不主动加载来源区块。来源的原料、能源和工作开关不参与判定。

启用 `proxyFactory.indirectLocators` 时，两种代理都可把另一台代理放在定位链中。按当前代理的主机栏顺序查找，同一个中转代理内也按其主机栏顺序查找。只读一层中转的直连机器记录，中转栏里的代理记录直接跳过。中转代理的定位器增删会自动反映到可用配方池；开工时重新检查两段定位，最终机器负责炉温等加工条件。正在运行的线程继续处理已提交的任务。

高炉池额外检查炉温：普通线圈机器使用线圈基础热量，加代理供电电压相对 MV 每级 100 K 的温度加成；诸神锻炉高炉模块直接使用当前 `getHeat()` 有效加工炉温，不叠加代理电压温度，不使用 `getHeatForOC()`。原机器的热量折扣、专属超频规则不随定位继承。

输入模式允许编辑定位器，禁止启动新线程；已经启动的线程继续完成。运行模式锁定定位器取放。定位器库存、槽位顺序和模式随世界和挖下的主机保存；缩小容量保留超额槽位，超额槽位可在输入模式取出。

手持已记录的定位器对空气右键可高亮主机 15 秒；潜行对空气右键会寻找主机附近有实地支撑、无碰撞与危险液体的落脚点，传送并高亮。支持跨维度，找不到安全位置时不传送。右键方块仍执行原有记录交互。导航由 `proxyFactory.locatorNavigation` 控制。

## 代理联合工厂

缺电、有线供电能力不足或无线账户余额不足导致跳停时，立即丢弃全部线程及其缓存产物，已投入的物品和流体不退回。输入舱室及总成内尚未投入线程的材料、工具和样板保留；手动暂停与结构停机保留线程进度。已经记录缺电跳停原因的存档不会恢复残留线程。此规则也适用于多线程联合代理。

LV 基础每线程并行 64、电压每升一级乘 4；LV 基础线程数 32、每升一级增加 8。HV 以上每级玻璃使速度增加 20 个百分点、耗电乘 0.9。四类有效参数模块（并行、速度、EU、超频）仍按原实现工作，线程仓不增加线程数；物品提示不再自动列出继承的模块说明。

普通输入和样板总成参与现有加工流程，跨配方类型样板可同时执行不同池。产物送入主机连接的 AE 网络，GUI 与 Waila 显示网络连接状态。高炉温度和 TST 梦魇工作台转换加工样板有专门支持；TST 桥接由 `proxyFactory.extremeCrafting` 控制。

UEV 及以上玻璃、且未安装普通或特殊能源仓时，自动使用所有者／队伍的 GT 无线 EU 账户；配方电压、线程和并行上限按 MAX 计算。每 tick 按实际耗电扣款，无线超频上限默认 0，可通过 OC 面板设置。安装能源仓后切回有线供电。开关为 `proxyFactory.wirelessPower`，默认开启。

需要一个维护仓及输入总线或输入仓；有线模式还需要能源仓。主机槽不再通过控制器物品解锁配方池。

## 多线程联合代理

采用原版量子操纵者完整 15×21×15 结构，脉冲操纵者和屏蔽核心固定最低级。底部可装输入总线、输入仓、普通或特殊能源仓及可选样板总成，顶部安装输出；不强制安装样板总成，无需维护、消声、催化剂或并行控制仓。

GUI 分为机器状态、主机栏和样板栏。输入模式允许编辑定位器与内部样板，运行模式启动新线程；已启动线程继续独立运行。样板栏默认 1024 个单样板槽，原生九列网格滚动展示；输入物、输出物、配方池三个搜索框支持 NECH 拼音，条件取交集，高亮匹配样板，所有格子保持原位置。搜索只改变展示，启动顺序仍按真实槽位编号。两种代理的主机栏也采用高亮搜索。鸿蒙之眼配方池 `gt.recipe.eyeofharmony` 无法通过两种代理解锁或启动，已编码的样板也无法绕过。

内部有效加工样板每槽对应一条线程，不读取总成内的线程样板。新线程依次尝试启动，前槽使用后的剩余原料与供电供后槽使用；前槽失败继续尝试后槽，不均分库存，也不使用共同并行。实际原料由输入总线、输入仓提供；样板总成继续作为输入总线支持，其共享槽能提供非消耗工具。目录内工具虚拟提供；目录外工具由实际输入、共享槽或主机唯一连接的 AE 网络提供可用状态（包括 PH 编程器电路库存／可合成状态），不提交合成任务。AE 主机节点需供电并占用频道；产物仍交付普通输出舱室。非消耗流体需实物；蓄水仓免普通水。

输入模式中键点击样板，在主机右上方设置四个附加参数。参数保存在独立 `gtnhadjustThread` NBT 下，保留原样板编码格式，可带去普通总成使用。首次解析配方后耗能分配初始化为基础 EU/t，其他参数为 -1。样板及参数保存在主机内，挖下主机时随主机保存，不散落。

| 参数 | 含义 |
| --- | --- |
| 预估产量 | 第一个编码产物每秒目标数量，物品/s 或 L/s；概率产物用期望值，-1 关闭计算 |
| 耗能分配 | 每线程总 EU/t 上限，包含并行和 OC；-1 不额外限制，默认配方基础 EU/t |
| 最大并行 | 此样板的并行上限；-1 使用全局上限 |
| 最大 OC | 此样板的超频次数上限；-1 使用全局上限，0 禁止 OC |

输入支持四则运算、括号及 k/m/g/t 数量后缀；耗能另支持 `1 LV`、`1A LV`、`32EU`、`32EU/t`、`32`，都表示 32 EU/t，`1LV*2` 和 `32*2` 得到 64。回车或离开输入框提交；无效输入保留原值。

提交产量或耗能后执行一次计算并回填并行与 OC，之后不在后台调优。先在全局并行参考值内增加并行，不足再增加 OC；仍不足时允许写入超过全局并行的估算。计算遵守线程耗能预算，忽略原料库存、批处理与输出等待。预算或整数范围内无法达标时保留最佳计算结果，面板显示配方估算速率。并行或 OC 超过全局值时以感叹号提示，但保留输入值。

真正启动时只读取耗能、并行和 OC，按全局并行／OC上限、线程耗能预算以及剩余供电和原料限制执行；预估产量不参与调度。普通 OC 耗能 ×4、耗时 ÷2，到 1 tick 停止；批处理仍可使用，但不参与产量估算。修改或取走样板只影响新启动，本批次已提交的原料、进度和产物独立保存；同一槽位仍有任务时不覆盖它，待其交付结束再启动新任务。

无普通或特殊能源仓时默认使用所有者／队伍的无线 EU 账户，电压 MAX；安装能源仓后使用有线供电。输出阻塞保留产物等待，暂停及结构停机保留线程；缺电跳停仍清除线程及缓存产物，已消耗原料不退回。定位来源与高炉炉温规则沿用上文。

`threadedJointProxy.voidUnlistedOutputs` 默认开启。每个线程开工时只把样板列出的物品和流体记入待输出产物，按原配方数量与概率结算；未列出的副产物也不会占用输出空间。换样板只影响下一批，已提交的线程按保存记录继续交付。

由 `threadedJointProxy`、`gtnrVirtualTools` 及 `threadedJointProxy.wirelessPower` 原有开关控制，新增容量配置 `threadedJointProxy.patternSlots` 默认 1024。适配 GTNH 2.9.0、GTNR 0.1.48／0.1.50、AE2 rv3-beta-1095 和 ModularUI2 2.3.94，两端同步配置并重启。`general.debug` 默认关闭，可查看定位检查、样板匹配、参数提交与实际线程启动。

游戏内验证：三页切换、1024 槽滚动及三个拼音搜索；中键参数及算式输入、超限提示、物品／流体图标提示；供电与原料不足时按真实槽位启动；运行中移走／修改样板，本批次继续完成；主机 AE 网络 PH 工具状态与总成共享工具；挖下再放置主机后样板及参数保留。

## 物质解压器

采用亚稳态黑洞遏制场的 35×35×33 布局。64 个霍金辐射重组焦点位置使用同级等级玻璃；超高密度弯曲机械方块位置允许舱室，背景辐射吸收机械方块保持结构用途。黑洞、球形约束场、向外喷流、双螺旋及扩散光环由本模组独立渲染。

放入对应维度／等级标记及编号电路：20 矿石、21 宝石、22 粉末、23 锭、24 流体。标记和电路不消耗；相同标记叠加提高产出，最高计 64 个。T0–T9 等级标记合并资源并排除较低等级已有产物，T10 汇总维度资源和固定太空采矿、钻井资源清单。

电压决定每线程并行能力，玻璃提高线程数并降低耗电与耗时。每轮统一分配线程、并行、无损超频和批处理。无能源仓时默认使用无线账户，也可安装能源仓供电；GUI 显示绿色总耗电，按 `1A MV` 等 GT 电压单位表示。资源配方由 `collector.singularityResourceRecipes` 控制，特效由 `collector.blackHoleRendering` 控制，无线由 `collector.wirelessPower` 控制，均默认开启。

物质解压器的并行上限适用于每条线程，三种机器（物质解压器、代理联合工厂、多线程联合代理）均不把全局并行值分摊为线程总配额。功率分配仍检查所有运行线程的合计耗电。

默认并行曲线为 `P(t) = round(64 × (2147483647 / 64)^((t - 1) / 13))`，电压等级 LV=1、MAX=14，每次升级约 ×3.79；LV／MAX 精确固定。手动设置为 0 时自动使用曲线值，其他值作为每条线程的额外上限。曲线由 `collector.baseParallel`（LV）及 `collector.maxVoltageParallel`（MAX）配置，旧 `voltageParallelMultiplier` 不再生效。

玻璃至少 HV；每高一级额外增加 4 线程。HV 耗能／耗时为 100%，之后各级减 15 个百分点，最低 1%。玻璃不再额外乘并行曲线；无线模式使用 MAX 电压。线程行明确显示含批处理的“本批总次数”，当前每线程上限在状态页和电力面板单独显示。旧版截图中的 67,108,864 是旧 MAX 并行 524,288 × 128 批，并非线程共享总上限。

`collector.directAeOutput` 默认开启。把 AE 线缆接到主机，节点供电并具有频道后，物品与流体直接注入该网络，每种产物一次最多提交 long 范围的数量；大整数账本记录全部余量，不把巨大产物展开为大量 int 大小的堆。网络已连接但空间不足／拒收时保留余量等待；节点断开、缺电、无频道或关闭开关时，回退原输出总线与输出仓。直接与回退路径共用同一份余额，部分交付后切换不会重复输出。现有输出舱室结构要求保留，GUI、Waila 与扫描信息均显示 AE 连接状态。机器耗能继续来自 GT 能源仓或无线账户。

适配 GTNH 2.9.0、GTNR 0.1.48／0.1.50、AE2 rv3-beta-1095；更新及配置变更后两端重启。`general.debug` 默认关闭，可查看每线程选择并行／OC、预算和 AE 接收数量。游戏内检查 MAX 每线程上限、多个线程同时启动、批处理显示；AE 接线／断线、缺频道、网络拒收及部分输出后切换舱室，核对物品和流体总量。

资源形态和来源清单见 [T10 材料形态](t10-material-forms.md) 与 [T10 矿石处理](t10-ore-processing.md)。

## 战利品模拟室

3×3×3 结构，中间放加热线圈，其他为洁净不锈钢机械方块及舱室。需要输入总线、输出总线和维护仓，输出仓可选；不耗电。工业屠宰场主机可无序合成为本机。

输入有生物灵魂瓶、刷怪笼或原版注册的刷怪蛋，每 6.4 秒模拟一次掉落，不消耗输入，不生成实体。同种生物每轮最多计 64 个；线圈每升一级，物品和经验倍率翻倍。使用 MobsInfo 战利品数据，过滤耐久装备、武器、工具和护甲；每个计入生物提供 120 L 液态经验，再乘线圈倍率。输出放不下的部分销毁，没有输出仓时不保留经验。

## 物质重塑仪

仅移植 EyeOfHarmonyBuffer 的 EV 简化模式，控制器 ID `31996`，结构固定 9×9×9。使用钨强化硼硅酸盐玻璃（`bartworks:BW_TieredGlass:2`）、稳定钛机械方块（`gregtech:gt.blockcasings4:0`）和洗矿机外壳（`miscutils:gtplusplus.blockcasings.2:4`）。洗矿机外壳位置允许输入总线、输入仓、输出总线和输出仓，四种舱室各至少一个；无需能源仓、维护仓和稳定环。完整位置由全息投影展示，结构材料与上游制作沿用 GTNH 2.9.0。

控制器用 8 个坚固钨钢机械方块、8 个 EV 发射器、8 个 EV 传感器、8 个 EV 力场发生器和 16 个 EV 电路在组装机制作，30 秒、1920 EU/t。不再注册完整结构、稳定环和鸿蒙粉／锭制造链，旧 `reshaping.simpleMode` 不再读取。

保留 16 条加工配方：橡胶、铂族、独居石、硅、钨、钛、氡、硅岩、干细胞、空气分离、海藻、聚合物、QFT 材料、催化剂、恒星物质和无尽材料。上游星门及组件配方和所有等级电路板配方均已移除。橡胶配方移除 PTMEG；催化剂配方移除星门水晶浆液；恒星物质配方移除熔融宇宙素和熔融磁流体约束恒星物质；无尽材料配方移除熔融磁物质和简并夸克胶子等离子体。

新增石头粉配方使用 1 号编程电路，消耗 2,100,000,000 个石头粉。14 种流体各产出 2,147,483,647 L，其中包括熔融磁物质和简并夸克胶子等离子体。

固定 64 秒一批，整机运行时消耗 1 MAX/t（2,147,483,640 EU/t），并行数与选配方次数不改变总耗能。成型需要至少一个普通或特殊能源仓，现有舱室位置可以安装。供电能力不足时等待，运行中缺电按 GT 规则跳停。配方无稳定环等级限制，每批顺序尝试 10 次选配方，每次最多 10 并行，同一配方可占用多次。保留输入分离、批处理、溢出保护及单配方锁定选项。

NEI 标志、机器提示沿用上游；普通及 Shift 提示最底部均显示“结构来源：EyeOfHarmonyBuffer”。`substanceReshapingDevice` 默认开启，控制机器、流体和配方注册。`general.debug` 默认关闭，开启后记录每批成功选择次数及输出堆数。适配 GTNH 2.9.0，客户端和服务端同步更新并重启。
