# Future Resource Protocol

FRP 是面向 GTNH 2.9.0 的独立模组，不依赖 GTNH Adjust。当前为开发测试版，包含便携预支终端、世界账本、AE 网络还款和 StructureLib 自动建造预支。

星门底座配方限制随世界账本债务更新，详细行为和兼容范围见下文。异常断电时世界数据与玩家背包分别保存，尚未验证跨文件事务恢复，建议仅在测试存档使用。

## 便携终端

0.1.17 支持从 FRP 标记或预支界面打开 BlockRenderer 的多方块结构详情后，点击原有“NEI 覆盖”按钮，直接将当前预览所需的方块种类加入世界标记，并返回 FRP 终端。材料读取沿用 BlockRenderer 伪合成样板使用的 `BRUtil.getIngredients`，跟随当前选择的结构等级、通道及预览材料；始终使用其 `hatchFilter` 排除舱室，不受原“过滤舱室”选项影响，覆盖输入/输出、能源、维护、消声、蒸汽等 GT 舱室及其子类。忽略方块数量，不生成样板、不自动预支、不增加债务；相同物品、meta 和 NBT 去重，既有标记时间保持原值。

服务端沿用原标记的会话、终端有效性、资格、阶段、NBT 大小及 900 项容量检查，分批最多 32 项，仅标记符合条件的内容，并汇总新增及跳过数量。标记和预支模式均可使用，独立于 `features.neiBookmarkImport`。启动开关为 `config/frp-features.properties` 中的 `structureOverlayMarks=true`，缺省开启；设为 `false` 后客户端不加载对应 Mixin，服务端拒绝该来源的标记请求。适配 GTNH 2.9.0、BlockRenderer6343 1.4.25、StructureLib 1.4.47 和 NEI 2.8.171，BlockRenderer 编译依赖通过 GTNH 2.9.0 清单解析。更新后客户端和服务端都使用 0.1.17 并重启，保持该开关一致。游戏内验证两种 FRP 模式、等级/材料切换、舱室过滤、重复标记、无资格材料、容量上限，以及关闭收藏导入时结构标记仍独立可用。


0.1.16 在标记界面左侧底部增加“从当前 NEI 收藏页导入”按钮。点击时读取当前选中的收藏页内全部分组和条目，包含滚动区域外的内容；不读取其他收藏页，不受 FRP 搜索、债务筛选或排序影响。只导入物品，跳过 NEI 能识别的流体及含流体容器收藏；保留物品 meta 和 NBT，忽略收藏数量，完全相同的物品去重。仅添加标记，不产生预支和债务。服务端逐项检查原有标记资格、阶段、协议状态、NBT 大小及 900 项容量；已标记物品保留原时间，新增物品记录导入时间。不符合条件或已满时跳过，并汇总新增与服务端跳过数量。

`features.neiBookmarkImport` 默认开启，独立于导出开关；关闭后禁止导入。兼容现有版本 2 账本及标记时间，适配 GTNH 2.9.0 和当前 NEI 收藏页 API；更新至 0.1.16 后客户端和服务端需同时更新并重启，开关保持一致。游戏内需验证多分组和长收藏页、切换收藏页、纯流体/含流体容器、重复项、NBT 变体、无资格物品、容量上限与关闭开关。

0.1.14 在终端左侧增加债务阶段和排序两个切换按钮，适用于标记与预支界面。阶段按“全部 → UHV → UXV → 全部”循环；UHV 只显示 UHV 阶段仍欠款的标记，UXV 只显示 UXV 阶段仍欠款的标记，不含 UHV 部分。预支界面的数量与悬停精确欠款跟随所选阶段；全部模式显示两阶段合计，并保留无债务标记。筛选与搜索可同时使用，只影响浏览，原有还款仍按 UHV 优先、UXV 随后结算，AE 还款和 NEI 导出仍处理全部债务。

排序按“NEI → 数量正序 → 数量倒序 → 标记时间正序 → 标记时间倒序 → NEI”循环。数量正序欠款多的在后，倒序欠款多的在前，数量采用所选阶段的剩余债务；标记时间正序早标记的在后，倒序早标记的在前。同值使用 NEI 顺序。按钮显示 ALL/UHV/UXV 与 NEI/Q+/Q-/T+/T-，悬停说明当前模式和下一项；切换时回到列表顶部。0.1.15 起，筛选和排序在点击切换时立即保存到客户端 `config/frp-client.cfg` 的 `terminal.stageFilter`（0=全部、1=UHV、2=UXV）与 `terminal.sortMode`（0=NEI、1=数量正序、2=数量倒序、3=时间正序、4=时间倒序）。关闭再打开任意终端、切换世界及重启游戏后继续使用上次选择；首次使用默认全部、NEI 排序。偏好只影响本客户端，无需服务端同步配置；沿用 `general.enabled` 开关，兼容现有版本 2 账本，更新模组后两端重启。

标记时间以服务端时间写入世界标记的 `markedAt` 字段，独立于物品 NBT。兼容 0.1.13 的版本 2 账本：首次读取时，为所有缺少时间的旧标记统一补写同一个时间并保存，已有时间、物品 NBT、债务与里程碑保持不变；旧标记之间按 NEI 顺序，新标记记录自己的时间。删除后重新标记使用新时间。此功能随 `general.enabled` 启停，无新增 Mixin；适配 GTNH 2.9.0、AE2 rv3-beta-1095 与当前 NEI，更新至 0.1.14 后客户端和服务端需同时更新并重启。

便携预支终端可在创造模式工具栏获取，也可用 1 个原版石头、1 个原版泥土和 1 根木棍无序合成 1 个。普通右键打开预支界面，潜行右键打开标记界面。两者使用相同的网格与搜索框，支持物品名、注册名和模组 ID 搜索，并接入 NEI 搜索提供器（安装 NECH 0.1.5 时支持拼音）；滚轮或拖动右侧滚动条浏览。搜索框支持长按退格和删除键。

终端打开时分配会话标识；打开期间如果手持物被切换或替换，界面会关闭。服务端调试日志会记录打开及关闭原因。

标记界面可将 NEI 物品拖入网格并松开，或携带 NEI 拖拽图标点击网格，也可手持物品点击网格来复制标记，不消耗实物；右键已有标记删除；如果该物品在任一阶段仍有世界债务，则不能删除其任何 NBT 变体的标记。两种界面沿用 AE 终端的背景和布局，默认按客户端 NEI 物品列表排序，可通过排序按钮切换，右键搜索框可清空搜索，使用鼠标上的背包物品点击搜索框，或从 NEI 拖拽物品到搜索框，即可按物品名称搜索且不消耗物品；鼠标悬停终端物品可使用 NEI 收藏、配方和用途等快捷键；预支界面显示该物品的世界总债务，零债务显示 0，欠款显示负数，大数缩写，悬停可查看精确值。聊天提示支持中文和英文。标记保存在世界账本中，所有便携终端共享，整个世界最多标记 900 项，不限制预支数量；完全相同的物品和 NBT 不重复，不同 NBT 变体分别占一项。由于 1.7.10 物品网络同步的压缩数据长度限制，NBT 数据过大时会拒绝添加。标记保存完整物品 NBT，债务按注册名与 meta 汇总，不区分 NBT。

预支界面左键取一组到鼠标，右键取半组到鼠标；Ctrl+左键取一个到背包，Shift+左键取一组到背包，Shift+右键取半组到背包。半组按物品最大堆叠数的一半向上取整，最大堆叠为 1 时取一个。鼠标已持有物品时，普通左键仍用于还款；普通右键仅可将同种物品追加到鼠标，且不超过堆叠上限。只有实际交付的数量会记账，背包或鼠标空间不足时只交付可容纳部分。

在预支界面中，用鼠标持有实物点击上方物品网格，或 Shift 点击下方背包里的物品，即可偿还该物品的世界债务。只消耗仍欠的数量，多余部分保留在鼠标或原背包槽内，零债务时不消耗；按照物品注册名和 meta 匹配，忽略 NBT。还款按 UHV 类债务优先，再还 UXV 类。调试日志记录实际结算数量；无需依赖背包空位来退回剩余物品。

`features.portableRepayment` 默认开启，设为 `false` 禁用便携终端的还款操作；修改后重启，客户端和服务端配置保持一致。

终端左侧前五个 AE 风格按钮分别为：保留搜索内容（默认关闭，开启后在本次客户端运行期间跨终端关闭/重开保留）；从无线 AE 网络还款；取消所有无债务标记；将全部世界标记和对应欠款导出到当前 NEI 收藏页的新分组；切换标记和预支界面。导出使用点击时的服务端账本快照，不受搜索过滤或当前滚动页影响；不同 NBT 标记分别导出，债务仍按注册名和 meta 汇总。无债标记按数量零导出（NEI 不显示零数量的数字），特别大的数量可能拆成多个收藏项。若异步接收期间切换 NEI 收藏页，则取消导出并提示重试。`features.neiBookmarkExport` 默认开启，关闭后不可导出；配置修改后重启，客户端和服务端保持一致。第三个按钮按世界账本的 ID 和 meta 检查两类债务，保留仍有债务的所有 NBT 变体。

AE 还款会检查背包、快捷栏和 Baubles 中注册为 AE 无线终端的设备，包括 GT-Never-Reset 0.1.34 二合一终端，选择第一个有电、处于无线范围内且有 AE 提取权限的网络；GTNH 2.9.0 使用 AE2 `rv3-beta-1095-GTNH` 和 Baubles Expanded 2.2.27。每次有实际提取的操作消耗 1 AE 电量，逐项尝试还款，按实际提取数量抵债，优先 UHV；缺少的资源保留债务。AE 还款后保留全部标记，可使用独立的无债标记清理按钮手动清除。未标记但仍在账本中的债务也可还款；NBT 不参与债务匹配。还款与清除结果会在聊天栏提示并同步所有打开的终端。`features.aeRepayment` 默认开启，设为 `false` 禁用 AE 还款；此功能也受 `features.portableRepayment` 控制，两项修改后重启，客户端和服务端保持一致。只能使用一个已连接网络，不会跨多个网络汇总。

## StructureLib 自动建造

在背包或快捷栏携带 FRP 预支终端时，StructureLib 1.4.47 多方块全息投影仪生存自动建造的材料来源在已有来源不足后查询世界标记；仅符合当前配方、阶段及黑名单规则的物品可用。模拟查询不记账，实际取得时按实际数量记入对应世界债务。与主模组 `structureLibAeAutoPlace` 同时启用时，先使用玩家库存及既有来源，再使用主模组 AE 来源，最后才使用 FRP。兼容基于 GTNH 2.9.0，GTNR 和主模组均非 FRP 运行依赖。此 Mixin 开关为 `config/frp-features.properties` 的 `structureLibAdvance`，缺省开启；要关闭可自行添加 `structureLibAdvance=false` 并重启客户端和服务端，关闭时不会加载对应 Mixin。UniMixins 是此功能的运行依赖。


## 星门底座配方限制

兼容旧存档：沿用版本 2 世界账本的键、债务分类和保存格式，保留全部标记及其时间、两类债务、里程碑、终止状态、世界级 `allowAllItems` 覆盖值和已有分类缓存，不迁移或重算既有债务。保留 `features.hullRecipeLocks`、锁定占位物注册名及旧配置默认行为。旧档首次进入时按原债务直接计算星门底座锁定状态；旧外壳配方移除仅存在于运行内存，完整重启更新后以模组正常注册的原配方为准。已有星门底座标记继续保留，但按新的受控物品规则不能预支；其他历史标记不会删除。

0.1.18 起，普通和无限制模式都改为锁定星门底座方块 `SGCraft:stargateBase@0` 的配方，UHV/UXV 机器外壳配方不再受 FRP 锁定。两类债务中只要有任意欠款就锁定星门底座，全部还清后解锁；账本异常时保持锁定。UHV/UXV 里程碑仍按原规则提交对应机器外壳，不改变债务分类、已存账本或最终终止规则。星门底座与内部锁定占位物不可标记或预支；原两种受控外壳从标记黑名单移除，仍遵循普通模式的配方/电压限制。

保留现有配置键 `features.hullRecipeLocks`，默认开启，现在控制星门底座配方限制。服务端启动世界时读取世界账本，首次预支产生债务后立即锁定，部分还款保持锁定，全部偿清后立即恢复，无需重启世界；仅锁定状态变化时刷新配方并向在线客户端同步，加入世界时也同步。精确匹配目标物品和 meta，覆盖工作台、Avaritia 9×9 极限合成及 GT 配方池；GTNH 2.9.0 的实际星门底座配方位于 Avaritia 9×9 列表。GT 配方移除时还会临时禁用原配方对象，阻止标准查找复用旧缓存；已启动并扣料的加工继续完成。

客户端同步 NEI 配方和星门底座红字锁定提示；退出世界或断开服务器时恢复原配方，切换世界后按新世界债务重新设置。已打开的 NEI 页面需关闭后重新查询。自定义动态输出或绕过上述配方管理器的加工流程需单独接入。适配 GTNH 2.9.0、GregTech 5.09.54、Avaritia 1.100、SGCraft 及 AE2 rv3-beta-1095，Avaritia 编译依赖由 GTNH 2.9.0 清单解析。更新至 0.1.18 后客户端和服务端同时更新并重启，配置保持一致。

资格索引支持静态工作台、熔炉及可枚举的 GT 配方，过滤 GT 禁用和展示假配方，识别 GT 副产物；没有识别到的配方在普通模式下拒绝。GT 电压等级按排序后的第一条有效配方判定，无有效电压归 UHV；同一物品首次预支时缓存分类。`recipes.additionalEligible` 可填写 `modid:item@meta` 补充资格；`recipes.classOverrides` 可填写 `modid:item@meta=UHV` 或 `=UXV`，覆盖对后续新预支生效，不修改既有债务。配置修改后重启。

`recipes.allowAllItems` 默认 `false`，作为世界尚未通过命令设置时的默认值。0.1.18 起，开启无限制模式后，标记与预支同时绕过配方存在、电压上限及 UHV 里程碑阶段检查，UXV、MAX 及更高电压等级物品也允许；星门底座、内部锁定占位物、最终终止和异常账本限制保留。无配方或无法识别电压的物品默认记为 UHV 类；已有有效电压信息的物品仍按原分类记账：低于 UHV 为 UHV 类，UHV 及以上为 UXV 类，`recipes.classOverrides` 和首次分类缓存仍生效。关闭无限制模式时，第一条有效 GT 配方 EU/t 大于 `GTValues.V[12]` 的物品仍按原规则禁止。配置默认值修改后重启；世界命令立即生效并持久化，优先于配置默认值。关闭后已有标记保留，预支时重新检查资格。

## 世界账本及开发命令

0.1.13 使用新版账本格式（版本 2），债务字段为 `uhvAdvanced`/`uhvPaid` 与 `uxvAdvanced`/`uxvPaid`，不迁移旧版账本。分类覆盖配置使用 `UXV`，最终里程碑命令使用 `uxv`。

全世界共用主世界的持久账本，初始只能预支 UHV 类；完成 UHV 里程碑后可预支 UXV 类。还款按 UHV 类、UXV 类顺序抵扣，不消耗超过剩余债务的物品。全部债务清零后完成 UXV 里程碑将永久停止正常预支。未知版本或损坏账本会锁定协议；不要删除账本来解决问题。

为本轮测试提供管理员命令（权限等级 2）：

- `/frp status`：查看两类总债务及阶段。
- `/frp held`：查看手持物品的债务与缓存类别。
- `/frp allowall`：查看本世界绕过状态；`/frp allowall on`、`/frp allowall off` 或 `/frp allowall toggle` 立即设置，需管理员权限。
- `/frp milestone uhv`：手持 UHV 机器外壳，在 UHV 债务清零后提交并消耗一个。
- `/frp milestone uxv confirm`：手持 UXV 机器外壳，在完成 UHV 里程碑且所有债务清零后提交并消耗一个；此操作终止预支，测试前请备份存档。

## 配置与兼容性

目标 GTNH 2.9.0，运行依赖 GregTech、AE2 和 NEI，客户端与服务端均需安装相同 FRP 版本及一致配置；兼容性仍需游戏内验证。`config/futureresourceprotocol.cfg` 的 `general.enabled` 默认开启，关闭后不注册终端或加载协议功能，已有世界数据不会删除，但也无法实施限制；修改后重启。`general.debug` 在开发测试阶段默认开启，记录配方索引统计、操作请求、标记、交付、债务与阶段变化，可能产生大量日志；可关闭并重启。日志前缀为 `[FRP debug]`。

更新至 0.1.18 后须重启客户端和服务端；ME 预支元件及其配置开关已移除，旧元件不再可用。重点验证任意电压物品在无限制模式下可标记和预支、普通模式仍限制 UXV 及以上物品、UHV/UXV 外壳正常制作、首次欠款锁定星门底座 9×9/GT 配方、部分还款仍锁定、全部偿清立即恢复、两类债务分别产生、读档/多人同步/切换世界后的状态，以及原有外壳里程碑。其余游戏测试建议覆盖：NEI 分组收藏数量和重进、拼音搜索、长按删除、持物切换界面、AE 按钮全额/部分还款及保留标记、无网络/无权限/欠电、Baubles 与 GTNR 二合一终端、无债标记清理、投影仪模拟与实际取材记账、与主模组并用、搜索保留开关、无序合成、NEI 与背包物品填充搜索、NEI 颜色及终端物品的收藏/配方/用途快捷键、多终端标记增删同步、有债务时禁止取消及还清后取消、全局债务显示和多个 NBT 变体、独立安装与主模组共存、NEI 拖拽和真实物品标记、NBT 变体、搜索和滚动、重复/无配方/受控星门底座拒绝、背包满与部分空间、UHV/UXV 权限、两类债务抵扣与里程碑、重进世界及跨维度共享。请保留客户端和服务端日志；实际启动与游戏内容测试由用户完成。

## 构建

在仓库根目录使用 Java 25，复用仓库 Gradle Wrapper 和项目内缓存：

```powershell
$env:JAVA_HOME = 'D:\CustomLib\zulu25.28.85-ca-jdk25.0.0-win_x64'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
$env:GRADLE_USER_HOME = "$PWD\.gradle-user-home"
$env:TEMP = "$PWD\.tmp"
$env:TMP = $env:TEMP
.\gradlew.bat -p frp build
```

NEI 和 AE2 编译参考文件为 `ref/libs/nei-instance.jar` 和 `ref/libs/ae2-instance.jar`；GT、StructureLib 和 Baubles Expanded 编译依赖从 2.9.0 版本清单解析。产物位于 `frp/build/libs/`。主项目仍使用原有构建命令；共享 Wrapper 不是模组运行依赖。
