# Future Resource Protocol

FRP 是面向 GTNH 2.9.0 的独立模组，不依赖 GTNH Adjust。当前为开发测试版，包含便携预支终端、世界账本、便携还款和 ME 预支元件；专用清算终端与 AE 网络还款尚未实现。

外壳配方限制在世界启动时按账本快照修改，详细限制和已知兼容边界见下文。异常断电时世界数据与玩家背包分别保存，尚未验证跨文件事务恢复，建议仅在测试存档使用。

## 便携终端

从创造模式工具栏获取便携预支终端；目前没有合成配方。普通右键打开预支界面，潜行右键打开标记界面。两者使用相同的网格与搜索框，支持物品名、注册名和模组 ID 搜索，滚轮或拖动右侧滚动条浏览。

终端打开时分配会话标识；打开期间如果手持物被切换或替换，界面会关闭。服务端调试日志会记录打开及关闭原因。

标记界面可将 NEI 物品拖入网格并松开，或携带 NEI 拖拽图标点击网格，也可手持物品点击网格来复制标记，不消耗实物；右键已有标记删除；如果该物品在任一阶段仍有世界债务，则不能删除其任何 NBT 变体的标记。两种界面沿用 AE 终端的背景和布局，按客户端 NEI 物品列表排序，右键搜索框可清空搜索；预支界面显示该物品的世界总债务，零债务显示 0，欠款显示负数，大数缩写，悬停可查看精确值。聊天提示支持中文和英文。标记保存在世界账本中，所有终端和 ME 预支元件共享，整个世界最多标记 900 项，不限制预支数量；完全相同的物品和 NBT 不重复，不同 NBT 变体分别占一项。由于 1.7.10 物品网络同步的压缩数据长度限制，NBT 数据过大时会拒绝添加。标记保存完整物品 NBT，债务按注册名与 meta 汇总，不区分 NBT。

预支界面左键取一组到鼠标，右键取半组到鼠标；Ctrl+左键取一个到背包，Shift+左键取一组到背包，Shift+右键取半组到背包。半组按物品最大堆叠数的一半向上取整，最大堆叠为 1 时取一个。鼠标已持有物品时，普通左键仍用于还款；普通右键仅可将同种物品追加到鼠标，且不超过堆叠上限。只有实际交付的数量会记账，背包或鼠标空间不足时只交付可容纳部分。

在预支界面中，用鼠标持有实物点击上方物品网格，或 Shift 点击下方背包里的物品，即可偿还该物品的世界债务。只消耗仍欠的数量，多余部分保留在鼠标或原背包槽内，零债务时不消耗；按照物品注册名和 meta 匹配，忽略 NBT。还款按 UHV 类债务优先，再还 UMV 类。调试日志记录实际结算数量；无需依赖背包空位来退回剩余物品。

`features.portableRepayment` 默认开启，设为 `false` 禁用便携终端的还款操作；修改后重启，客户端和服务端配置保持一致。

## ME 预支元件

创造模式工具栏获取 ME 预支元件；只有便携终端可增删世界标记，元件不再提供标记界面。放入 ME 驱动器后，已标记且符合世界权限的物品作为虚拟库存提供给网络。普通 AE 存储来源按 AE 原有优先级决定，只有本元件实际提取的数量产生债务；模拟提取和库存查询不记账。本元件拒绝所有存入，不能用它偿还债务。`features.aeAdvanceCell` 默认开启；关闭后不注册元件及其处理器，修改须重启、客户端和服务端保持一致。关闭前应先取出并妥善保管已有元件。

本轮适配 GTNH 2.9.0、AE2 `rv3-beta-1095-GTNH`；仅在能确定服务端世界且处于服务端线程时允许元件提供资源，缺少宿主上下文时安全拒绝。已加载网络会在世界标记、里程碑或终止状态改变时请求刷新，元件继续向 AE 显示 2.1G 虚拟数量，实际提取每次重新验证权限。ME 箱界面和其他第三方宿主、异步提取、断网及大量自动化尚需游戏内验证；当前未提供元件合成配方。

## 机器外壳静态配方限制

`features.hullRecipeLocks` 默认开启；服务端每次启动世界时读取世界账本，对 UHV、UMV、UXV 机器外壳的生产配方应用一次静态快照。UHV 债务限制 UHV 与 UMV 外壳，UMV 债务限制 UMV 外壳；最终里程碑完成前限制 UXV 外壳。工作台的兼容有序矿辞配方增加不可正常获得的清算提示物品，匹配到的 GT 机器配方直接禁用。退出世界时恢复原配方，重新进入时依据新世界账本重新设置。

**债务增加、偿还或里程碑改变不会立即改变现有快照，必须重启世界或服务端才会更新锁定和解锁。**因此启动后新产生的债务在重启之前不会锁住此前已解锁的配方；这是静态方案的实际边界。远程客户端的 NEI 由客户端本地配方生成，可能无法显示服务端的静态修改。第三方自定义工作台配方类型可能不支持修改；启动日志的 `unsupported` 数量不为零时可能存在绕过路径。机器配方和工作台配方均需在测试存档中实测，不能将本轮视为已验证的防绕过保证。修改开关后重启，客户端与服务端配置应一致。

资格索引支持静态工作台、熔炉及可枚举的 GT 配方，过滤 GT 禁用和展示假配方，识别 GT 副产物；没有识别到的配方默认拒绝，不保证覆盖动态配方和所有其他模组。UHV、UMV、UXV 机器外壳不可标记或预支。GT 电压按排序后的第一条有效配方判定，无有效电压归 UHV；同一物品首次预支时缓存分类。`recipes.additionalEligible` 可填写 `modid:item@meta` 补充资格；`recipes.classOverrides` 可填写 `modid:item@meta=UHV` 或 `=UMV`，覆盖对后续新预支生效，不修改既有债务。配置修改后重启。

`recipes.allowAllItems` 默认 `false`；设为 `true` 后，标记和提取无需生产配方，但三种受控外壳仍被禁止，阶段与终止权限仍生效。已有可识别配方的物品仍按配方分类，没有可用电压信息时归 UHV 类。修改后重启，客户端和服务端配置保持一致。

服务端启动完成时建立配方索引，以包含其他模组在加载完成阶段注册到 GT 配方池的配方；输出各阶段进度。异常的工作台配方或 GT 配方池会记录具体错误并跳过，受影响的配方可能无法用于预支。默认配置下，未识别到的物品不会因跳过错误而自动获得资格。若启动仍失败，需检查 `fml-client-latest.log` 中 `FRP recipe` 和 `[FRP debug]` 附近的记录。

## 世界账本及开发命令

全世界共用主世界的持久账本，初始只能预支 UHV 类；完成 UHV 里程碑后可预支 UMV 类。还款按 UHV 类、UMV 类顺序抵扣，不消耗超过剩余债务的物品。全部债务清零后完成 UMV 里程碑将永久停止正常预支。未知版本或损坏账本会锁定协议；不要删除账本来解决问题。

为本轮测试提供管理员命令（权限等级 2）：

- `/frp status`：查看两类总债务及阶段。
- `/frp held`：查看手持物品的债务与缓存类别。
- `/frp settle`：以手持真实物品结算，消耗不超过该物品债务的数量。
- `/frp milestone uhv`：手持 UHV 机器外壳，在 UHV 债务清零后提交并消耗一个。
- `/frp milestone umv confirm`：手持 UMV 机器外壳，在完成 UHV 里程碑且所有债务清零后提交并消耗一个；此操作终止预支，测试前请备份存档。

## 配置与兼容性

目标 GTNH 2.9.0，运行依赖 GregTech、AE2 和 NEI，客户端与服务端均需安装相同 FRP 版本及一致配置；兼容性仍需游戏内验证。`config/futureresourceprotocol.cfg` 的 `general.enabled` 默认开启，关闭后不注册终端或加载协议功能，已有世界数据不会删除，但也无法实施限制；修改后重启。`general.debug` 在开发测试阶段默认开启，记录配方索引统计、操作请求、标记、交付、债务与阶段变化，可能产生大量日志；可关闭并重启。日志前缀为 `[FRP debug]`。

更新至 0.1.4 后须重启客户端和服务端；旧测试设备内的标记不会迁移，请使用新的测试世界。游戏测试建议覆盖：多个终端与 AE 网络之间的标记增删同步、有债务时禁止取消及还清后取消、全局债务显示和多个 NBT 变体、独立安装与主模组共存、NEI 拖拽和真实物品标记、NBT 变体、搜索和滚动、重复/无配方/受控外壳拒绝、背包满与部分空间、UHV/UMV 权限、两类债务抵扣与里程碑、重进世界及跨维度共享。请保留客户端和服务端日志；实际启动与游戏内容测试由用户完成。

功能需求见 [FRP 功能设计](../docs/FRP.md)，后续技术方案与尚待验证问题见 [FRP 技术设计](../docs/FRP-technical-design.md)。

## 构建

在仓库根目录使用 Java 25，复用仓库 Gradle Wrapper 和项目内缓存：

```powershell
$env:JAVA_HOME = 'D:\CustomLib\zulu25.28.85-ca-jdk25.0.0-win_x64'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
$env:GRADLE_USER_HOME = "$PWD\.gradle-user-home"
$env:TEMP = "$PWD\.tmp"
$env:TMP = $env:TEMP
.\gradlew.bat -p frp build
```

NEI 与 AE2 编译参考文件为 `ref/libs/nei-instance.jar` 和 `ref/libs/ae2-instance.jar`；GT 编译依赖从 2.9.0 版本清单解析。产物位于 `frp/build/libs/`。主项目仍使用原有构建命令；共享 Wrapper 不是模组运行依赖。
